# 腾讯云部署、更新与恢复

现有服务使用腾讯云香港 Lighthouse（Ubuntu），正式域名 `footballknow.art`。代码在 `/opt/footballknow`；账号、密钥、会话与私人预测在 `/var/lib/footballknow`。服务为 `footballknow-web`、`footballknow-worker` 和 `caddy`，网站程序只监听 `127.0.0.1:8765`，Caddy 提供 HTTPS。

## 更新现有网站

本版附 `footballknow/deploy/update.py`。使用已核对的 GitHub 提交归档及 SHA-256，不能把未经检查的 `main` 当前内容直接当成固定版本。

1. 在本地完成测试、浏览器检查、凭据扫描，提交到指定仓库，记录完整 40 位提交号。
2. 下载 `https://codeload.github.com/hkmszcxyyykf4632/12/tar.gz/<完整提交号>`，计算归档 SHA-256。
3. 登录腾讯云该实例的执行命令入口，下载同一提交归档，核对 SHA-256，再从归档取得已经审阅的 `footballknow/deploy/update.py`。
4. 用 root 执行：

```sh
python3 /安全暂存目录/update.py --archive /安全暂存目录/release.tar.gz --sha256 <已核对的SHA256> --revision <完整提交号>
```

更新脚本核对路径、文件类型、Python 语法、五项赛事球队和积分榜；保留比归档更新的线上快照；停止同步任务；备份将替换的公开程序和服务文件；逐文件原子替换；更新服务配置；检查五项赛事分析接口后启动同步。发布前备份位于 `/var/backups/footballknow/expanded-<版本>-<时间>`。脚本不替换账号数据库或 API 密钥。应用健康检查失败时恢复本次替换文件。

本次企业版还调整了 Caddy 的 JSON 缓存规则。先计算并审阅当前 `/etc/caddy/Caddyfile` 的 SHA-256，确认它只包含预期网站配置，再向命令添加 `--caddy-base-sha256 <当前配置摘要>`。脚本仅在摘要相符时备份并更新 Caddy，先执行配置校验，再重载；失败时恢复备份。未提供此选项时不会修改正在运行的 Caddy 配置。恢复带有此更新的版本时，也需把备份中的 `Caddyfile` 恢复到 `/etc/caddy/Caddyfile`，验证后重载。

服务权限：web 可写私人状态、五项赛事阵容缓存及股价历史目录；worker 可写公开快照和私人来源缓存。不要删除这些目录，也不要让私密状态进入 `public`。

## 发布后核对

```sh
systemctl is-active footballknow-web footballknow-worker caddy
journalctl -u footballknow-worker -n 80 --no-pager
curl --fail http://127.0.0.1:8765/api/auth/me
curl --fail https://footballknow.art/release.json
```

检查 56 项任务的实际成功时间，五项赛事积分榜和可用名单数量。浏览器打开正式域名，点击新功能并检查手机布局。旧 AI 报告不会自动重新生成；管理员可主动更新一份报告，确认新阵容证据进入请求且结论仍为两至三段。

## 暂停与恢复后台同步

进入网站管理后台登录，使用“暂停同步”或“恢复同步”。开关只允许管理员修改，状态写入 `/var/lib/footballknow/sync-control.json`，重启后仍有效。暂停会停止当前同步子进程并阻止新任务启动，已有数据与网站继续可读；不会删除数据或关闭网站。正常暂停时健康接口显示 `paused`。恢复默认最多同时运行 2 项任务，`FOOTBALL_SYNC_WORKERS` 可设为 1–8；比分、赔率和行情优先。`FOOTBALL_SYNC_OVERRIDES` 可按任务单独增加间隔。资料任务的实际周期和错误退避见同步监控。

股票预测保存在私密 `stock-forecasts.sqlite3`；与账号和 API 设置一起做私人备份。公司公告、俱乐部资料每天检查，历史价格与预测结果每小时检查。

## 恢复

优先使用已知正常的上一提交归档重新执行更新，并保留当前私人状态。需要精确恢复本次公开文件时，先停 web/worker，读取该备份 `manifest.json`：`existed` 中的文件从 `app/` 复制回原位置；`files` 中本次新建的文件仅删除明确列出的条目；两个 service 文件复制回 `/etc/systemd/system`，运行 `systemctl daemon-reload` 并启动服务。备份目录、目标目录必须逐一确认；不要清空整个 `/opt` 或私人状态目录。

## 新服务器首次安装

先配置域名 DNS 指向新服务器，并仅开放需要的 SSH、HTTP、HTTPS 入口。把 `footballknow` 目录复制到 `/opt/footballknow`。在可信本机运行 `manage.py init-admins` 生成初始种子，然后通过私密渠道将生成的 `state/admin-seed.json` 放到服务器 `/opt/footballknow/deploy/private/admin-seed.json`，限制访问；该文件不在 GitHub。

确认 `deploy/Caddyfile` 的域名与新环境一致后，root 执行 `sh /opt/footballknow/deploy/install.sh`。该首次安装脚本会安装运行依赖并配置 Caddy，仅适用于已确认的专用实例；共用其他网站的服务器须先合并 Caddy 配置。已有实例日常更新使用上面的 update.py。

私密备份单独保存 `/var/lib/footballknow`、Caddy 配置及证书状态，记录权限和拥有者。恢复账号或密钥应使用私人备份，不从公开仓库猜测或重置。
