# 维护、扩展及验证

## 日常检查

先看网页“数据说明”的最近成功时间，再看后台同步任务。快照过期与网站无法打开是两件不同的事。源站访问限制时保留最后成功数据，不将空响应覆盖为零。书商官网检查失败不代表整个足球数据服务失败。

管理员密钥只在服务端配置；更换 DeepSeek 密钥在后台保存后，用一场下一场分析验证。现有模型名为 `deepseek-flash`，供应商模型以后变更时应先核查其官方接口，再修改默认配置和验证脚本。仅改页面文字不会训练模型。

备份服务器 `/var/lib/footballknow` 才能保留管理员、密钥与预测记录；这些文件必须存放在私人备份位置，不提交公开 GitHub。个人模拟数据在浏览器，使用页面导出另行备份。

## 测试

```sh
python -m pytest -q
npm ci
npm test
```

覆盖认证和私密配置、赛事隔离、赛前预测冻结、加时点球口径、赔率金额精度、备份导入、积分一致性、榜单缺失、真实比赛身份、替补分钟、同生日不同球员、过滤条件保留和 HTML 转义。测试读取仓库公开快照；快照赛季切换时应同步调整测试夹具，不能只改期望值掩盖问题。

真实浏览器还应检查：三赛事切换；总榜与主客场；中文／粤语球员搜索；已完赛比赛及首发；关注；赔率时间与来源；两段结论与详情展开；390 px 手机宽度；网页控制台错误。自动测试通过不替代浏览器、服务器服务状态与正式域名验证。

## 增加联赛或功能

1. 先在 `football/leagues.py` 与网页 `league.mjs` 定义独立标识和公开目录。
2. 增加适配器，核对赛季、赛程阶段、球队 ID、中文名与上游授权／访问方式；沿用已有模型，不让不同赛事同号数据混用。
3. 在 worker 注册独立任务，确定检查间隔、缓存、重试和最后成功状态。
4. 增加身份、缺失、赛季切换与页面交互验证，再本地浏览器检查。
5. 按腾讯云更新说明部署、核对版本和服务，记录实际验证结果。

付费会员以后单独加入账号申请、订单与微信商户回调校验、重复通知幂等、到账开通、退款状态和管理员查询；尚未实现，不应显示为可购买服务。手机号绑定规则也待用户正式恢复该项需求后实现。

## 已知限制

名单、转会、历史报价和中文名并非全部覆盖。球员榜只收录来源前 50；纪律榜受来源更新频率限制。比赛日期按来源日期筛选，显示开球时间按本地时区。关注与模拟记录不跨设备同步。AI 需管理员主动生成，新数据不会自动改写已保存报告；看生成时间，必要时更新。

页面没有复制懂球帝的新闻、论坛、版权比赛视频或会员体系。本轮选择的是数据中心、比赛中心、阵容、交锋和关注这些实用功能。
