# 架构、数据来源与分析方法

## 文件与数据流

| 目录／文件 | 职责 |
| --- | --- |
| `server.py` | FastAPI 页面、认证、分析、比赛详情接口 |
| `worker.py` | 25 项独立定时任务；失败保留上次成功快照 |
| `football/` | 赛事适配、身份核对、数据模型、分析与评价 |
| `public/` | 原生模块化网页，以及英超公开 JSON |
| `public/laliga`、`public/ucl` | 分赛事公开快照 |
| `public/*/match-details` | 核对身份后的比赛阵容缓存；文件名为摘要值 |
| `analysis-rules.txt` | 管理员可调整的详细分析规范默认文本 |
| `state/` 或 `FOOTBALL_STATE_DIR` | 账号、会话、密钥、AI 报告、首次预测和来源缓存；不公开 |
| `tests/` | 数据口径、认证、赔率模拟、页面交互和赛事隔离验证 |

同步脚本从上游读取数据，核对赛事、赛季、球队与比赛身份，再原子发布 JSON。网页每三十秒读取公开快照。比赛详情接口只能查询已知比赛，不能让访问者指定任意上游 URL。各赛事分别保存报告与首次预测，同号球队不会混用。

## 赔率来源核查

[Bet365](https://www.bet365.com/hub/en-gb/football)、[Betfred](https://www.betfred.com/sports/football)、[BetVictor](https://www.betvictor.com/en-gb/sports/football)、[bwin](https://sports.bwin.com/en/sports/football-4)、[Paddy Power](https://www.paddypower.com/football)、[Betfair Exchange](https://www.betfair.com/exchange/plus/en/football-betting-1)、[Pinnacle](https://www.pinnacle.com/en/soccer/)、[William Hill](https://sports.williamhill.com/betting/en-gb/football)。研究时也核查了 [Ladbrokes](https://www.ladbrokes.com/en/sports/competitions/football/english/premier-league)。

官网可能返回访问限制或只有空壳页面；来源检查区逐项展示结果，`directFeed` 为 false。实际历史报价来自 [Football-Data 字段说明](https://www.football-data.co.uk/notes.txt) 对应 CSV；赛前部分报价来自 ESPN。`BFD` 是 Betfred，`BFE` 是 Betfair Exchange，不混用。只有主胜、平局、客胜三项都完整有效才收录；市场平均不是另一家书商。报价附实际采集途径、时间和市场范围，无法保证每场每家公司都有报价。

美式报价先换成十进制；历史收盘与早期快照分开。交易所未扣佣金，不能直接视为普通公司赔率。未来比赛只采用匹配赛季、日期、主客队的报价，不用别场补缺。

## 阵容及下一场分析

已完赛名单核对来源比赛 ID、日期、主客队和队内球员唯一性。11 人首发才标完整；位置分组图是名单示意，不是实际跑位。分钟若上游未直接提供，会按换人／红牌时间估算，标“约”，不计补时；未知时间保留空值。

下一场请求提供最近最多二十场已收录正式比赛、当前赛事赛季战绩、主客场统计、泊松基线、转会、领队、可用人员、历史阵容覆盖、常用阵型、首发频次、七／十四天已知分钟与赔率快照。历史首发不等于下一场确认首发；缺失场次不等于休息；阵容变化与结果相关，不自动解释为因果。

本地基线计算进球均值与泊松比分分布，汇总 90 分钟主胜／平／负；详见 `football/analysis.py`。规则要求核对样本、时间衰减、主客差异、中立场、市场水位、信息缺失与不确定性，不准制造未训练的修正系数。DeepSeek 仅输出结构化 pick、summary、details，后端校验格式；结论两至三段，细节折叠。规则摘要值和生成时间随报告保存。

首次赛前预测单独登记，赛后结算不被后续生成覆盖。历史逐场回测与真实前瞻预测分开；计算命中率时必须有分母，不能把提示词长度或历史回测当成未来保证。
